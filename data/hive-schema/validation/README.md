# Hive Data Validation Automation

Python-based validation framework that executes test cases against the synthetic Hive schema via beeline JDBC. Validates row counts, transformations, aggregates, and supports regression and integration testing.

## Architecture

```
validation/
├── config.py                # Connection settings, table metadata, status mappings
├── beeline_executor.py      # Beeline JDBC execution utility (subprocess wrapper)
├── test_row_counts.py       # TC-RC-*: Row count validations across layers
├── test_transformations.py  # TC-TF-*: Type conversion, status expansion checks
├── test_aggregates.py       # TC-AG-*: Balance/amount sum consistency
├── test_regression.py       # TC-RG-*: Snapshot-over-snapshot regression detection
├── test_integration.py      # TC-IG-*: Cross-table join integrity, FK checks
├── report_generator.py      # Text, HTML, and JSON report generation
├── run_validations.py       # Main CLI runner orchestrating all modules
└── README.md
```

## Quick Start

```bash
# Full validation for a snapshot date
python run_validations.py --as-of-dt 2024-01-31

# With regression comparison to previous month-end
python run_validations.py --as-of-dt 2024-01-31 --as-of-dt-prev 2023-12-31

# Override JDBC connection
python run_validations.py --as-of-dt 2024-01-31 \
    --jdbc-url jdbc:hive2://hive-prod:10000 \
    --user my_user --password my_pass

# Run specific categories only
python run_validations.py --as-of-dt 2024-01-15 \
    --categories row_count,transformation

# JSON report only, verbose logging
python run_validations.py --as-of-dt 2024-01-31 \
    --report-formats json --verbose
```

## Test Categories

### Row Counts (TC-RC-*)
- **TC-RC-001**: Every table has data for the partition
- **TC-RC-002**: Source → staging counts (td_contracts → cad_id, cad_cb, cad_nccb)
- **TC-RC-003**: Staging → audit counts (cad_cb → actg_fact, cad_nccb → nc_actg_fact)
- **TC-RC-004**: Both DAILY and MOEND records present

### Transformations (TC-TF-*)
- **TC-TF-001**: MM/DD/YYYY → DATE parsing (no NULL gaps)
- **TC-TF-002**: Amount parsing (comma removal, non-negative)
- **TC-TF-003**: Status code expansion (ACT→ACTIVE, CLO→CLOSED, etc.)
- **TC-TF-004**: Credit score INT range (300–850)
- **TC-TF-005**: data_src_ind valid values ('D' or 'M' only)

### Aggregates (TC-AG-*)
- **TC-AG-001**: SUM(ln_curr_bal) source vs staging
- **TC-AG-002**: SUM(ln_orig_amt) staging vs audit
- **TC-AG-003**: SUM(ln_escrow_bal) staging vs audit
- **TC-AG-004**: Payment component sum = total payment
- **TC-AG-005**: SUM(borr_ann_incm) source vs cad_id

### Regression (TC-RG-*)
- **TC-RG-001**: Row count change between snapshots (threshold: 10%)
- **TC-RG-002**: Balance total change between snapshots (threshold: 15%)
- **TC-RG-003**: Loan status distribution (no disappeared statuses)

### Integration (TC-IG-*)
- **TC-IG-001**: All 7 tables have data for the partition
- **TC-IG-002**: Source → cad_id join (no orphans)
- **TC-IG-003**: Staging → audit fact join (no orphans)
- **TC-IG-004**: Fact → dimension FK integrity (arrg_dim_sk)
- **TC-IG-005**: No duplicate records on natural keys
- **TC-IG-006**: DAILY/MOEND account set alignment

## Configuration

Set via environment variables or `config.py` defaults:

| Variable | Default | Description |
|----------|---------|-------------|
| `BEELINE_JDBC_URL` | `jdbc:hive2://localhost:10000` | Hive JDBC connection string |
| `BEELINE_USER` | `hive` | Beeline user |
| `BEELINE_PASSWORD` | *(empty)* | Beeline password |
| `BEELINE_EXTRA_ARGS` | *(empty)* | Extra beeline flags (Kerberos, SSL, etc.) |
| `QUERY_TIMEOUT_SECONDS` | `300` | Per-query timeout |
| `REPORT_OUTPUT_DIR` | `./reports/` | Report output directory |

## data_src_ind Logic

All tables include a `data_src_ind` column:
- **`'D'` (DAILY)**: Business-day snapshots loaded every trading day
- **`'M'` (MOEND)**: Month-end snapshots loaded on the last business day

Tests run against both values to ensure complete coverage.

## Reports

Three report formats are generated by default in `./reports/`:
- **Text** (`.txt`): Human-readable console-style summary
- **HTML** (`.html`): Styled table report for browser viewing
- **JSON** (`.json`): Machine-readable for downstream automation/CI
